Retail AI Helper
Complete Technical Documentation
Architecture • RAG • Embeddings • Persistent Vector Store • FastAPI • React

Purpose: This document records how the Retail AI Helper was designed and implemented, why each layer exists, how the components communicate, how data flows through the system, how the project was tested, and what the next development stages are.
1. 1. Project Overview
The Retail AI Helper is a retrieval-augmented generation (RAG) application for a retail store. It allows a user to ask natural-language questions about store information and receive answers grounded in the store's own documents.
The project was intentionally built incrementally. The first objective was to understand the fundamentals of Gemini, embeddings, document ingestion, semantic search, and RAG before adding a web API and frontend.
2. 2. Goals of the System
Allow customers or staff to ask natural-language retail questions.
Use store-provided documents as the knowledge source rather than relying only on the model's general knowledge.
Retrieve the most relevant document chunks for each question.
Give Gemini only the relevant retrieved context and instruct it not to invent information.
Persist document embeddings so they do not have to be regenerated for every question.
Expose the RAG system through a FastAPI backend.
Provide a React/Vite chat interface for users.
Return both the generated answer and the retrieved source documents.

8. 8. Embeddings
An embedding converts text into a high-dimensional numerical representation. Texts with similar semantic meaning can have vectors that are closer to each other than unrelated texts.
The project successfully tested gemini-embedding-001 and observed 3072-dimensional vectors.
def create_embedding(text):
    response = client.models.embed_content(
        model="gemini-embedding-001",
        contents=text
    )
    return response.embeddings[0].values
A transient 503 UNAVAILABLE error was encountered during embedding work. A retry wrapper was added as a reliability improvement so temporary API failures can be retried before failing.

11. Document Loader
loader.py reads supported text files from the documents directory and returns metadata including the source filename, path, and text.
from pathlib import Path

SUPPORTED_EXTENSIONS = {
    ".txt"
}

def load_text_file(file_path):
    path = Path(file_path)
    with open(path, "r", encoding="utf-8") as file:
        return file.read()

def load_documents(directory="documents"):
    documents = []
    directory_path = Path(directory)

    for file_path in directory_path.iterdir():
        if file_path.suffix.lower() not in SUPPORTED_EXTENSIONS:
            continue

        text = load_text_file(file_path)

        documents.append({
            "source": file_path.name,
            "path": str(file_path),
            "text": text
        })

    return documents
12. Text Cleaning
cleaner.py removes unnecessary spacing and normalizes blank lines before chunking.
import re

def clean_text(text):
    text = re.sub(r"[ \t]+", " ", text)
    text = re.sub(r"\n\s*\n+", "\n\n", text)
    text = text.strip()
    return text
13. Chunking
Chunking divides long documents into smaller pieces. The current learning implementation uses a word-based chunk size of 500 words and an overlap of 100 words.
def chunk_text(text, chunk_size=500, overlap=100):
    words = text.split()
    chunks = []
    start = 0

    while start < len(words):
        end = start + chunk_size
        chunk = " ".join(words[start:end])
        chunks.append(chunk)
        start += chunk_size - overlap

    return chunks
The overlap helps preserve context across chunk boundaries when documents become longer. With the current small sample documents, each source produced one chunk.

After chunking, every chunk is sent to gemini-embedding-001. The resulting vector is attached to the chunk before persistence.
for chunk in chunks:
    chunk["embedding"] = create_embedding(chunk["text"])
The successful test showed 3072 dimensions for the generated embeddings.
12. 16. Semantic Search
The system uses cosine similarity to compare the user's question embedding with stored document embeddings. A higher cosine similarity means the vectors are more aligned in the embedding space.
import numpy as np

def cosine_similarity(vector_a, vector_b):
    vector_a = np.array(vector_a)
    vector_b = np.array(vector_b)

    dot_product = np.dot(vector_a, vector_b)

    magnitude_a = np.linalg.norm(vector_a)
    magnitude_b = np.linalg.norm(vector_b)

    return dot_product / (magnitude_a * magnitude_b)

14. 18. Basic RAG Pipeline
RAG means Retrieval-Augmented Generation. Instead of asking Gemini to answer entirely from its general model knowledge, the application first retrieves relevant project/store information and places that information in the generation prompt.
User question
     ↓
Create question embedding
     ↓
Compare with stored document embeddings
     ↓
Sort by similarity
     ↓
Take top_k chunks
     ↓
Build context
     ↓
Send context + question to Gemini
     ↓
Generate grounded answer
19. RAG Retrieval Code
def retrieve(question, top_k=2):
    chunks = load_vectors()

    question_embedding = create_embedding(question)

    results = []

    for chunk in chunks:
        score = cosine_similarity(
            question_embedding,
            chunk["embedding"]
        )

        results.append({
            "source": chunk["source"],
            "text": chunk["text"],
            "score": score
        })

    results.sort(
        key=lambda item: item["score"],
        reverse=True
    )

    return results[:top_k]

The generation prompt instructs Gemini to use only retrieved context, avoid inventing facts, and state when the context is insufficient.

15. 21. Persistent Vector Storage
The first RAG implementation generated embeddings for all source chunks every time a question was asked. That is acceptable for learning but inefficient for an application.
Persistent storage changes the architecture so document embeddings are generated during ingestion and saved. At query time, only the user's question needs a fresh embedding.
BEFORE:

Question
  ↓
Load documents
  ↓
Chunk documents
  ↓
Embed every document
  ↓
Search
  ↓
Gemini


AFTER:

ONE-TIME INGESTION
Documents → chunks → embeddings → vector_store/store.json

EVERY QUESTION
Question → query embedding → load stored vectors → similarity search → Gemini
22. Persistent Store Implementation
import json
from pathlib import Path

STORE_PATH = Path("vector_store/store.json")

def save_vectors(chunks):
    STORE_PATH.parent.mkdir(parents=True, exist_ok=True)

    data = []

    for chunk in chunks:
        data.append({
            "chunk_id": chunk["chunk_id"],
            "source": chunk["source"],
            "chunk_index": chunk["chunk_index"],
            "text": chunk["text"],
            "embedding": chunk["embedding"]
        })

    with open(STORE_PATH, "w", encoding="utf-8") as file:
        json.dump(data, file)

def load_vectors():
    if not STORE_PATH.exists():
        raise FileNotFoundError(
            "Vector store not found. Run the ingestion pipeline first."
        )

    with open(STORE_PATH, "r", encoding="utf-8") as file:
        return json.load(file)

24. Persistence Verification
Persistence was verified by temporarily renaming the original documents directory and then running the RAG test. The application still returned the correct Basmati-rice answer and the same retrieved sources. This demonstrated that the query was using the persisted vector store rather than reading the original documents during the query.

The vector store represents application knowledge: product FAQs, policies, store information, and future project documentation. Conversation history is different: it represents user/assistant messages from a particular chat session.

        "sources": [

                "similarity": source["score"]

18. 30. CORS and the Browser
The React application runs on localhost:5173 while FastAPI runs on 127.0.0.1:8000. Because these are different browser origins, FastAPI must explicitly allow the frontend origin. The CORSMiddleware configuration handles the browser's OPTIONS preflight request and allows the subsequent POST /chat request.
An initial OPTIONS /chat 405 error occurred because the CORS configuration was missing or not active. After adding CORSMiddleware and restarting FastAPI, the frontend was able to receive the response.

25. 38. Current Limitations
The persistent vector store is a JSON file and is intended for learning/POC use, not large-scale production workloads.
The current chunker is word-based and does not yet use document structure such as headings or sections.
Only .txt documents are currently supported by the loader.
There is no PostgreSQL database yet for conversations.
The current RAG pipeline retrieves by cosine similarity without a dedicated reranking stage.
There is no authentication or user account system.
There are no product/inventory tools yet.
The application currently uses local development servers.

43. 44. Troubleshooting Notes
Chroma compatibility
The project initially explored Chroma for vector storage but encountered compatibility/native-module issues in the Python 3.14 environment, including an hnswlib-related error. The project therefore used NumPy and a simple persistent JSON vector store to learn the mechanics without blocking progress.
Python version
The local environment uses Python 3.14. The project avoided forcing a Python downgrade and instead used the manual vector-search approach for the learning stage.
Gemini transient 503
A temporary embedding service error occurred. Retry logic was introduced so transient failures can be retried.
FastAPI CORS 405
The React browser first generated OPTIONS /chat and received 405. CORS middleware was then configured for localhost:5173 and 127.0.0.1:5173, after which the React request succeeded.
PowerShell npm execution policy
PowerShell blocked npm.ps1. npm.cmd was used instead, avoiding the need to change the machine's execution policy.

46. 47. Conclusion
The Retail AI Helper has progressed from a standalone Gemini API experiment into a working end-to-end RAG application. The implementation now has document ingestion, chunking, embeddings, semantic retrieval, persistent vector storage, Gemini answer generation, a FastAPI backend, and a React chat interface.
The most important architectural separation is now established: ingestion prepares and persists knowledge; query-time RAG retrieves relevant knowledge; Gemini generates the grounded response; FastAPI exposes the capability; and React provides the user interface. Future production work can add conversation persistence, structured product data, live inventory tools, better vector storage, authentication, and improved retrieval.
